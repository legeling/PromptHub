# 文档边界与旧项目迁移

仅在文档归属不清或正在迁移旧流程时读取。

## 按内容寻找已有落点

| 信息 | 优先落点 |
|---|---|
| 最新确认的需求、业务规则、验收 | 每主题唯一权威文档；新项目按需使用 docs/specs/<topic>.md |
| 实施动作、进度、关键阻塞 | 原活动计划，引用权威需求；不另存需求定义 |
| 无法从代码理解的重要取舍 | 功能文档中的原因；独立长期决策才新增 ADR |
| 测试如何运行 | 现有测试说明、配置或 README；功能文档引用 |
| 过去的方案和完成记录 | Git、已有历史记录；不作为当前执行依据 |

不要求所有项目使用相同目录。主题、设计、验收可在同一文件分节；拆分应服务维护，不是满足阶段编号。
文档入口只列已有的有效主题与需要继续的计划，不预建所有分类索引。

## 渐进迁移

1. 确认本轮获准范围，检查工作区。定位旧 AGENTS、规则和入口；只检查相关规则，不在功能任务里顺手审计全仓库历史。
2. 对照新流程，列出要替换的旧门禁：先读所有阶段、每次新建 change、强制编号链、全量收敛、状态与物理移动绑定。保留项目特有安全、数据、构建和发布约束。
3. 原位修改获准的规则片段。入口登记现有的有效文档；已有 workflow、knowledge、topology 路径可以继续使用，不要求迁入 specs。
4. 确认每主题唯一权威文档，把最新确认的需求原位写入，旧要求与验收同步替换；实施尚未完成则标为待实施。相关现行文档和 AGENTS 的需求、验收副本改为引用，不再抄写新规则；保留原命令和其他无关内容。历史正文或入口说明失效及现行文档。
5. 仅在用户授权清理的范围内归档或删除。保留历史也可避免误导：默认读取和检索排除历史范围，历史正文不作为行动指令。
6. 核实本次主题的现行说法、验收和引用一致，计划没有过期待办。无需为每一份旧记录补 ID 或年份目录。

## 回滚

迁移前保留所改文件的差异或备份。回滚只恢复本次改动，不覆盖迁移之后的用户修改。
脚手架的 --force 只备份并替换三个目标文件。备份位于项目外的用户状态目录，可通过 SPEC_INIT_BACKUP_ROOT 指定项目外位置；按备份中的 RESTORE.txt 恢复 files/ 下文件，保留后续编辑。不能用强制覆盖代替人工合并规则。
Skill 安装器的 --force 先复制、校验新版，再替换已有完整安装；失败恢复旧版，恢复失败则保留恢复目录并报告。成功替换不保留个人定制，更新前应另行备份到技能发现目录之外。
