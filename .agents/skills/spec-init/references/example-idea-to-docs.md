# 简短示例

## 一个普通功能

用户要求：发票列表增加“仅看逾期”。已有发票功能说明，就在原文中增加对应行为与验收，不新建日期需求或五文件 change。

实施前只需明确：

- 目标：用户能筛选尚未收款且已超过到期日的发票。
- 边界：沿用现有时区和到期规则，不增加催款通知。
- 验收：已收款的不出现；未来到期的不出现；到期边界符合现有规则。
- 验证：复用现有发票状态测试，补必要筛选回归；引用实际测试路径，不虚构文件和通过结果。

用户确认后就在原功能文档中更新需求与验收，尚未实现标为待实施；实现后更新交付状态和验证引用。其他文档引用此处，不重复抄写规则。

## 同一需求改变

活动计划原为“自动提醒”，用户明确改为“只显示提醒列表，暂不发送通知”。

立即在原权威功能文档中把“自动发送通知”替换为“只显示提醒列表”，同步替换验收条件；代码未改完则标为待实施。
定向查找相关 README、AGENTS、设计和计划中的“自动发送”旧约定，纠正或改为引用权威文档。计划撤下发送任务，只保留落实新需求的动作；旧讨论标明已失效与现行入口。
下一轮从更新后的需求继续，不能因为旧实现尚未移除，就把已取消的发送要求当成有效需求。

## 小修复
