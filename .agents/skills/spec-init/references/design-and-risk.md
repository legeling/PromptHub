# 完整设计与高风险变化

仅在用户要求完整需求、完整设计，或当前变化涉及高风险边界时读取。

## 用户明确要求完整设计

围绕指定范围展开：用户与目标、主流程与异常流程、实体和状态、模块与接口、权限边界、依赖和运行方式、验收及质量目标。
写清关键方案的取舍，区分已确认约定和待决策项。已有内容引用即可；无需固定数量的文件或独立测试目录。
用户只要求方案时不擅自实施；用户同时要求实施时，在关键决策明确后继续完成实现和验证。

## 按风险补充

| 变化 | 必要问题与验证 |
|---|---|
| 权限、隐私、安全边界 | 谁可以做什么；越权和拒绝路径如何验证；敏感信息如何隔离 |
| 数据迁移或持久化语义 | 旧数据如何兼容；部分失败、重复执行、恢复和回滚如何处理 |
| 公共 API 或共享契约 | 现有调用者的影响；兼容窗口或升级顺序；契约和失败路径测试 |
| 并发、性能、大规模处理 | 输入规模与资源上限；复杂度、瓶颈和测量；取消及资源回收 |
| 发布或不可逆外部动作 | 获准边界、真实环境验证、停止条件和恢复办法 |

只补本轮相关内容。记录可在原功能文档或活动计划中，重大长期决策才另建短 ADR。
不能为了减少文档忽略关键未知风险；也不能因缺少通用测试教材、追踪编号或历史归档而阻塞无关工作。
