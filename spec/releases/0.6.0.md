# PromptHub 0.6.0 Release Record

## Release

- Version: `0.6.0`
- Tag: `v0.6.0` (not created)
- Date: Unreleased
- Channel: Stable
- Status: Preparation

## Preparation Scope

- The first release candidate used `0.6.0-beta.1`. The current candidate uses
  `0.6.0-beta.2` across Root, Desktop, CLI, self-hosted Web, Cloudflare
  Worker, Mobile, and Expo metadata. Stable promotion will replace that
  identity with `0.6.0`.
- Private shared packages retain their independent `0.1.0` package versions.
- Public website badges, introductions, and download URLs continue to point to
  the latest explicit stable release record, currently `0.5.9`.
- Localized README stable labels and download links remain on `0.5.9` until
  signed artifacts and other distribution outputs have been published.
- The accepted storage target is SQLite authority for structured records,
  relationships, annotations, version metadata, and settings; the filesystem
  owns actual packages, attachments, media, and required historical contents.
  The earlier file-first/rebuildable-SQLite model is not the selected 0.6.0
  baseline. Conversion and upgrade acceptance remain in progress under
  [the foundation requirements](../changes/active/foundation-integrity-redesign/specs/foundation/spec.md#fr-foundation-003-data-ownership-and-invariants).
- Main/Core ownership of renderer persistence, secret isolation, restore/root
  recovery, and consistent portable snapshots must satisfy that same boundary.
  This release record does not claim migration or release acceptance is complete.
- The shared SQLite migration foundation is verified against tagged `v0.4.7`,
  `v0.4.8`, `v0.5.1`, and `v0.5.2` fixtures. Historical issues #89, #97, and #98
  remain in progress until their exact path/portable/upgrade-snapshot application
  fixtures converge under `legacy-upgrade-recovery-audit`.

## Unreleased Mainline Integration (2026-10-12)

- PR #222 and #223 are integrated into main; their contribution-branch version
  names do not change the mainline `0.6.0` target or current `0.6.0-beta.2`
  build identity.
- The unreleased changelog and all seven product READMEs summarize quick/batch
  tags, shared batch actions, startup-folder restore, search, editor and
  empty-state guidance, backup access, Prompt hierarchy, localized errors, and
  Web folder visibility. These summaries are not amendments to the published
  beta.2 package or claims of complete GUI/packaged acceptance.
- Signed macOS packaging, required release-asset checks, current SQLite settings
  ownership, and managed-copy-only Rules restore remain the mainline contracts;
  fork-only release scripts and obsolete IndexedDB persistence are excluded.
- Public stable badges/downloads and the website continue to use the explicit
  published stable record. Development badges link to `Unreleased`, not to a
  nonexistent mainline `v0.6.4` release.

## Publication Gates

- Complete the `0.6.0` changelog from the final release contents and replace
  `Unreleased` with a dated stable entry.
- Promote `0.6.0` from `preparation` to `stable record` in the release index
  only after public artifacts are available.
- Run `pnpm verify:release` before tagging or publishing.
- Build, sign, notarize, and verify required desktop artifacts through the
  standard release workflow.
- Publish and verify CLI, self-hosted Web, Worker, Mobile, release assets, update
  manifests, and configured mirrors as applicable.
- Refresh public website metadata and localized README release copy only after
  the corresponding public artifacts are available.

## Rollback

The mainline documentation reconciliation changes no product version, schema,
user data, or published artifact. It can be reverted independently and the
website regenerated from the unchanged stable record. Published beta.1/beta.2
records, tags, and downloads must not be removed or rewritten as part of that
rollback. Any later candidate identity change follows its own release record.
