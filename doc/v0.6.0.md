## 1. 迭代点 F1【功能】Rules 备份导入静默覆盖修复

对应上游 open issue #210/#209（数据丢失级，已确认存在于 0.5.9 基线且上游未修）。

- **改动点**：`packages/core/src/rules-workspace.ts` 备份导入路径不再无条件写穿用户目标文件。导入前逐条预检：
  1. 目标文件被用户在 PromptHub 外部编辑过（managed vs target 哈希不一致，复用既有 `syncStatusForMeta`）→ 判为 **conflict**，不写 managed/target、**不清空本地版本历史**，交回既有冲突解决流程处理
  2. 备份记录内容为空串且目标当前非空 → 判为 **skip-empty**，防止目标被清零
  3. 其余记录按原语义正常导入
- **实现思路**：新建 `packages/core/src/rules-backup-io.ts`（165 行）承载导出 + 导入 + 结果摘要（`imported / conflicts / skipped`），依赖注入解耦；主文件删除对应函数体与本地类型（定义下沉至新模块并 re-export，消费方零改动）。新增显式逃生参数 `forceOverwriteTargets?: boolean`（默认 false）保留旧覆盖能力。IPC 信封扩展为 `{ success, imported, conflicts, skipped }`（`success` 字段保留，向后兼容），preload/renderer 对缺字段旧信封做可选链防御。restore 流程把冲突/跳过的结构化明细写入 console 日志，消除"静默"属性。
- **功能影响范围**：Desktop 备份恢复、设置页拖拽恢复；CLI `rules import` 与 `workspace snapshot restore`（返回摘要，行为默认获得保护，调用点丢弃返回值兼容不破坏）；IPC `rules:importRecords` 契约扩展。**无 DB schema 变更、无存储布局变更。**
- **测试**：`rules-workspace.test.ts` 新增 5 用例（干净导入摘要 / 外部编辑冲突保护 / 空内容跳过 / 强制覆盖逃生口 / 全新项目导入），红→绿全程 test-first；顺带修复该套件 Windows 兼容 bug（硬编码 `/tmp` → `os.tmpdir()`，基线上整套 rules 存储测试在本机因此全红，修复后仅余 3 个路径分隔符类既有失败）。

## 2. 迭代点 F2【功能】自托管 Web 分类无法保存修复

对应上游 open issue #219（100% 复现 422，已确认存在于 0.5.9）。

- **改动点**：`apps/web/src/services/prompt.service.ts` 的 create/update：请求**未显式携带 visibility** 时，由目标 folder 的 visibility 推断，消除"新建分类默认 shared + prompt 默认 private → 任何归入操作必 422"的产品死锁。
- **实现思路**：`resolveInferredVisibility(actor, folderId, fallback, intent)` helper——**推断仅在 actor 权限可合法持有时生效**；非管理员指向 shared 分类时回落原 private 语义，保持既有 422 验证错误类不变（此边界由上游路由契约测试 `prompts.test.ts:467` 锚定，实现中途曾以 403 越界、被该测试当场拦截后修正）。update 仅在"文件夹实际变更"时推断，folder 不变的历史错配行编辑行为与原版完全一致；推断变更同样持久化到 `visibility` 列。
- **功能影响范围**：仅自托管 Web 服务端；桌面端本地库不经过此校验，零影响；显式传 visibility 的请求路径零改动。**非破坏性：只把原必失败（422）的路径变为成功，其余路径逐一由测试锁定。**
- **测试**：`prompt.service.test.ts` 新增 9 用例（双向往推断 / 持久化回读 / 无分类默认不变 / 显式失配仍 422 / 非管理员边界回落），先红后绿；`src/routes/prompts.test.ts` 既有全量用例同步转绿。

## 3. 迭代点 E2【体验】批量 Prompt 标签操作

fork 定制「右键添加标签」的自然延伸；补齐批量操作矩阵（上游多选 toolbar 已收藏/移动/删除，唯缺标签）。

- **优化位置**：表格视图多选批量栏（`PromptTableView`）、共享弹窗 `QuickTagModal`、workspace 接线层。
- **调整方案**：
  - `QuickTagModal` props 从 `prompt: Prompt | null` 升级为 `prompts: Prompt[]`（右键单条入口以 `[prompt]` 传入，交互零感知）；多条时标题显示「为 N 个提示词打标签」，当前标签区展示选中项**交集**，候选建议区排除交集
  - 添加/移除对全部选中项逐条应用；按条粒度合并结果——部分失败只回滚失败条目，成功条目保持已持久化，toast 报 `{failed} of {total} prompts failed to update`
  - 表格视图选中后批量栏出现「标签」按钮（HashIcon，风格与批量收藏一致），经 `openQuickTagForIds` → workspace dialogs 态打开弹窗
  - 新增 6 个 i18n key × 7 locale 全覆盖
- **用户实际收益**：给 30 条提示词补同一个标签从「右键 30 次」变「多选 → 1 次确认」；交集视图避免"看起来会改别人标签"的信息模糊。
- **输入输出保证**：不新增业务规则、不改 DB/IPC；写入仍走既有 `prompt.update`（tags 字段），单条行为与 0.5.9 完全一致（由既有单条用例回归锁定）。

## 4. 迭代点 F4【功能】QuickTagModal 回滚加固（fork 自身债务）

- **改动点**：0.5.9 重放的定制组件内部三处问题。复核结论如实修正：原候选描述的"回滚 bug"实际因 React stale-closure 巧合表现正确，**不存在用户可见故障**；本次将巧合行为显式化并补真实缺口。
- **实现思路**：① 批量重写中移除 stale-closure 依赖，`applyTagsToSelection` 按条目记录 outcomes 精确合并；② 保存进行中的 Enter 竞态封锁（`isLoading` 守卫，按钮此前已有 disabled、键盘路径是漏洞）；③ 清理无效 `fetchPrompts` 引用。
- **功能影响范围**：仅该弹窗组件与其 11 条组件测试（含局部失败、竞态、交集显示、批量移除的按条断言）。
