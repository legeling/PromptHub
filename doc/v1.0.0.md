## 2. 迭代决策背景

本次迭代起点是一次 fork 同步策略评估。本地定制仅约 700 行（4 个文件），而上游 3 个版本跨度的功能彼此耦合在共享数据层与新模块中。逐功能 cherry-pick 到 v0.5.6 底座的冲突成本远高于整体对齐后重放定制，故采用：

**路线 A：整体对齐上游稳定版 v0.5.9 + 在 v0.5.9 新架构上重放定制**（用户确认选定）。

明确不跟进项：上游 v0.6.0-beta 的「文件优先 canonical 存储架构重写」与「统一 Agent 工作台」等 beta 特性（未达稳定，上游仍在修复期）。
